# Phira Web

A **browser (WebAssembly) port** of Phira. Built from the original Phira v0.8.2 sources with Rust + macroquad/miniquad and compiled to `wasm32-unknown-unknown`, so it runs directly in any modern browser with no installation.

[简体中文](./README.md) | English

[![License: GPL-3.0](https://img.shields.io/badge/License-GPL--3.0-blue.svg)](./LICENSE)

## Features

- Runs entirely in the browser — no client install, just open the page
- Most desktop features are available: song select, chart preview, judgement, scores and local records, respacks (skins), mods, localization
- In-memory VFS persisted to IndexedDB, so charts and settings survive a reload
- WebAudio backend with a single global mixer for UI sounds and music
- Keyboard and multi-touch input
- Multiplayer: phira-mp byte streams are carried over a backend HTTP tunnel (browsers cannot open raw TCP)
- Extension-less asset endpoint `/__res` and same-origin proxy `/__proxy` to bypass download managers and browser CORS

## Layout

```
phira/             Game core (Rust)
prpr/              Engine
prpr-avc/          AVC video decoding
prpr-l10n/         Localization
prpr-pbc/          PBC chart format
prpr-auto-offset/  Auto offset
phira-monitor/     Monitor tool
phira-main/        Desktop entry point (not required for Web)
vendor/            Patched dependencies shipped in-repo (sasa, getrandom, phira-mp-common)
web/               Web shell plus build/run scripts
  index.html         Page skeleton + first-load progress bar
  index.php          PHP backend (static files / __res / __proxy)
  .htaccess          Apache rules (MIME, headers, rewrite)
  gl.js              miniquad WebGL / event layer
  gl_extra.js        Extra WebGL bindings
  host.js            Host bindings (storage, clipboard, inputs, key forwarding)
  sasa_web.js        WebAudio backend
  build.ps1          Build script
  start.bat          One-click launcher (local server + browser)
  serve.py           Local static server
  assets/ mod/ rank/ respack/  Game assets
  pkg/               Build output (not committed; generated by the build script)
tools/             Build helper scripts (patch_glue.py)
```

## Build

### 1. Install the wasm target

```powershell
rustup target add wasm32-unknown-unknown
```

### 2. Provide wasm-bindgen

Pick one:

- Put a prebuilt `wasm-bindgen-<version>` directory under `tools/` in the repo root (the script adds its `wasm-bindgen.exe` to `PATH`);
- or install it globally: `cargo install wasm-bindgen-cli --version 0.2.114`;
- or download the official release and add its directory to `PATH`.

> The version must match the `wasm-bindgen` version pinned in `Cargo.lock`, otherwise the wasm module fails to load at runtime.

### 3. Build

From the repository root:

```powershell
pwsh web/build.ps1
```

The script runs:

1. `cargo build -p phira --target wasm32-unknown-unknown --release --no-default-features --features chat`
2. `wasm-bindgen --target web` producing `web/pkg/phira.js` and `web/pkg/phira_bg.wasm`
3. `tools/patch_glue.py` to merge miniquad's `env` imports into the wasm-bindgen glue, and writes an empty `web/pkg/env.js`
4. Copies the root `assets/` into `web/assets/`

Notes:

- The script prefers `D:\Rust` and `D:\python` (the author's local paths) and falls back to the system `PATH` when they do not exist. If your Rust/Python live elsewhere, edit the variables at the top of `web/build.ps1`.
- Building serially (`-j 1`) is recommended; a high parallel job count may fail with `os error 112` when disk space runs out.
- `phira-main` (the desktop build) is not part of the Web build; use `cargo build -p phira-main` separately if you want it.

### 4. Run locally

```powershell
python web/serve.py
```

Then open <http://localhost:8000/>, or double-click `web/start.bat` (starts the server and opens the browser).

The first load shows a progress bar with download progress, speed and estimated time remaining.

## Deploy to a web server

The Web build is a static site plus two tiny server endpoints, so it runs on any PHP-capable host.

**Prerequisite:** the frontend hard-codes `/__res` and `/__proxy` as absolute site paths, so deploy at the **domain root** (`https://your-domain/`), not in a subdirectory.

**Upload the contents of `web/`:**

| Item | Purpose |
|---|---|
| `index.html` | Page shell, loading overlay, fullscreen button |
| `index.php` | PHP backend: static files, `/__res`, `/__proxy` |
| `.htaccess` | Apache rules (MIME, headers, rewrite); ignored by nginx |
| `gl.js`, `gl_extra.js`, `host.js`, `sasa_web.js` | miniquad / host JS glue |
| `pkg/` | `phira.js`, `phira_bg.wasm`, `env.js` (build output) |
| `assets/` | Built-in respack (backgrounds, fonts, sounds, icons) |
| `mod/`, `rank/`, `respack/` | Mod icons, grade icons, hit effects |
| Loose `*.png` / `*.jpg` / `*.ogg` / `*.ttf` | Assets loaded directly by the game (`background.jpg`, `button.ogg`, `font.ttf`, …) |

In short: upload **everything except** `build.ps1`, `serve.py`, `serve.ps1` and `start.bat` (about 55 MB).

`.htaccess` is a dot-file — many FTP clients hide dot-files by default, so make sure it is really transferred, otherwise `/__res` and `/__proxy` return 404.

With nginx (`.htaccess` is ignored — add these rules to the site config or the "URL rewrite" box in your hosting panel):

```nginx
location / {
    try_files $uri $uri/ /index.php?$args;
}
```

`wasm` must be mapped to `application/wasm` (Apache does it via `AddType` in `.htaccess`; nginx: `types { application/wasm wasm; }`), otherwise the browser will not stream-compile the module.

For local verification you can also use PHP's built-in server (`PHP_CLI_SERVER_WORKERS` has no effect on Windows):

```powershell
$env:PHP_CLI_SERVER_WORKERS=8; php -S 0.0.0.0:8000 index.php
```

## Differences from the desktop build

- **File system**: no real FS under wasm; replaced with an in-memory VFS persisted to IndexedDB, so charts survive reloads
- **Audio**: sasa's WebAudio backend (`ScriptProcessorNode` pull model) with a single global mixer
- **Asset loading**: all game assets go through the extension-less `/__res` endpoint (`text/plain`, `inline`) to avoid download managers hijacking them
- **Input**: keyboard events are captured at the document level and forwarded to the canvas; text input (login, prompts) uses an in-page HTML overlay instead of `window.prompt`
- **Network**: a same-origin `/__proxy` proxy works around browser CORS
- **Multiplayer**: browsers cannot open raw TCP, so the phira-mp byte stream is handed to a backend "HTTP tunnel" (`POST /__mp/open`, `/__mp/send`, `/__mp/tunnel`). Protocol encoding (`vendor/phira-mp-common`) is shared with the desktop build. The tunnel base URL comes from `window.__phiraMpBase`

## Known limitations

- **Chart export / respack features are unavailable**: those paths rely on `std::thread::spawn`, which panics on single-threaded wasm
- The first load downloads roughly 9 MB of wasm plus game assets; a longer black screen on slow networks is expected
